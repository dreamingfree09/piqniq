# Piqniq agent instructions

The Project Owner and Aether own planning, architecture and significant approvals. Codex implements authorised assignments and publishes verification evidence. Start at README.md, Docs/CONTINUITY.md and Docs/GHP-01.md. Also read and preserve .github/copilot-instructions.md: its existing quality, security, privacy, documentation and npm test requirements remain applicable.

Work only in the authorised Piqniq checkout. Inspect actual Git top-level, current branch, local changes and existing origin before mutation. Preserve code, history, configuration, dependencies and visibility. Do not publish .env contents, credentials, tokens, user data, uploads, logs or database dumps. Documentation-only installation does not authorise starting servers, seed/bootstrap scripts, account changes, live database mutation or deployment.

Use unique work IDs and producer-owned branches with explicit file scope. No new agent, orchestration service, paid API or automation is required. Worker owns routine verification and Git publication through authorised tools. Normal scoped commits/pushes require no repeated permission; main integration requires explicit exact-revision authorisation. No force pushes, history rewrites, branch deletion or new remotes.

Follow GHP-01 for exact base/received/final revisions, approval, scope, validation, evidence, limitations, acknowledgement and integration states. Publish a complete PR handover or one producer record, then read back the exact branch and contents. CODEX DONE triggers Aether's independent GitHub review; it does not authorise merging.

Documentation changes require complete diff/parent, link, conflict-marker, whitespace and publication checks. For code changes run npm test as required by existing Copilot instructions, using an isolated test environment with disposable data. Run relevant browser/API/runtime checks for affected behaviour and record actual results. Never point tests or seed/cleanup scripts at a live database without explicit authorisation. Report unavailable test dependencies as blockers, not passes. Preserve authentication, authorisation and input validation.
